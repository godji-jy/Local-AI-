# Local AI

ผู้ช่วย AI ส่วนตัวที่รันในเครื่องของคุณเอง ใช้ [Ollama](https://ollama.com) เป็นตัวรันโมเดล และ [Gradio](https://gradio.app) เป็นหน้าเว็บ ข้อมูลที่คุยและไฟล์ที่แนบไม่ถูกส่งไปที่ไหน (ยกเว้นตอนเปิดโหมดค้นหาเว็บ ซึ่งจะส่งคำค้นไปยัง DuckDuckGo/Wikipedia)

## ความสามารถ

- 💬 แชตภาษาไทย / อังกฤษ / อัตโนมัติ ตอบแบบสตรีมทีละข้อความ
- 📎 **แนบไฟล์ / วางด้วย Ctrl+V** แล้วถามเกี่ยวกับเนื้อหาในไฟล์ (txt, md, pdf, docx, csv, json และไฟล์โค้ด)
- 🖼️ **ดึงรูปจาก PDF/Word** มาแสดงในคำตอบตรงตำแหน่งที่เกี่ยวข้อง
- 🖼️ **วางรูปที่คัดลอกไว้ (Ctrl+V)** หรือแนบรูป แล้วให้ AI ดูและตอบ (ต้องใช้โมเดลที่อ่านรูปได้)
- 📚 **ฐานความรู้ในเครื่อง** ใส่ไฟล์ลงโฟลเดอร์ `knowledge` แล้วให้ AI ค้นและอ้างอิงตอนตอบ (RAG)
- 🔎 **ค้นหาเว็บ** เปิดอ่านหน้าเว็บจริง เลือกเฉพาะส่วนที่ตรงคำถาม พร้อมแหล่งอ้างอิงท้ายคำตอบ
- 🧩 **แยกหน้าที่โมเดล** คำถามโค้ดไปที่โมเดลเขียนโค้ด (`qwen2.5-coder:3b`) คำถามทั่วไปไปที่โมเดลหลัก เลือกอัตโนมัติหรือบังคับเองได้
- 🧰 **โหมดทำงานกับไฟล์ (Cowork)** ให้ AI ดูรายการ อ่าน ค้นหา สร้าง และแก้ไฟล์ในโฟลเดอร์ทำงานที่กำหนดให้เอง
- 🕘 **ประวัติแชต** บันทึกอัตโนมัติ ปิดแอปแล้วเปิดใหม่ยังอยู่ เลือกเปิดแชตเก่า และลบได้
- 🧠 **โหมดคิดลึก** ให้โมเดลคิดก่อนตอบ ช้าลงแต่เหมาะกับโจทย์ยาก

## สิ่งที่ต้องมี

- Python 3.10 ขึ้นไป
- [Ollama](https://ollama.com/download) ติดตั้งและเปิดอยู่
- โมเดลใน Ollama 2 ตัว:

```bash
ollama pull qwen3.5:4b     # โมเดลตอบคำถาม (เปลี่ยนได้ที่ MODEL ใน backend/config.py)
ollama pull bge-m3         # โมเดลสร้าง embedding สำหรับฐานความรู้ / ค้นเว็บ / ไฟล์ยาว
ollama pull qwen2.5-coder:3b   # โมเดลเขียนโค้ด (ไม่บังคับ ถ้าไม่ติดตั้งจะใช้โมเดลหลักตอบแทน)
```

## ติดตั้ง

```bash
# สร้างและเปิด virtual environment (Windows)
python -m venv .venv
.venv\Scripts\activate

# ติดตั้งแพ็กเกจ
pip install -r requirements.txt
```

ถ้าอยากให้เปิดเป็นหน้าต่างโปรแกรมแทนเบราว์เซอร์ (ไม่บังคับ):

```bash
pip install pywebview
```

## วิธีรัน

```bash
python app.py
```

- ถ้าติดตั้ง `pywebview` จะเปิดเป็นหน้าต่างโปรแกรม
- ถ้าไม่ได้ติดตั้ง ให้เปิดเบราว์เซอร์ไปที่ http://127.0.0.1:7860

## วิธีใช้งาน

### แชตทั่วไป
พิมพ์คำถามในช่องข้อความแล้วกดส่ง หรือกดการ์ดหัวข้อยอดนิยมตอนเริ่มต้น

### ตั้งค่า (เมนู ⚙️ ด้านล่าง)

| ตัวเลือก | ทำอะไร |
|---|---|
| ภาษา | เลือกให้ตอบเป็นไทย อังกฤษ หรืออัตโนมัติตามคำถาม |
| 🔎 ค้นหาเว็บ | ค้นเว็บและอ่านหน้าเว็บก่อนตอบ (ต้องต่ออินเทอร์เน็ต) |
| 📚 ใช้ฐานความรู้ในเครื่อง | ค้นจากไฟล์ในโฟลเดอร์ `knowledge` |
| 🧠 คิดลึก | ให้โมเดลคิดก่อนตอบ ช้ากว่าแต่แม่นขึ้นในโจทย์ยาก |

> ค่าเริ่มต้นของสวิตช์ค้นหาเว็บและฐานความรู้คือ **ปิด** ต้องเปิดเองก่อนใช้

### โหมดทำงานกับไฟล์ (Cowork)
ให้ AI ทำงานกับไฟล์ในเครื่องให้ เช่น "สรุปทุกไฟล์ในโฟลเดอร์นี้เป็น summary.md", "ในไฟล์ todo.md ติ๊กว่าส่งงานเสร็จแล้ว", "ค้นหาว่าไฟล์ไหนพูดถึงงบประมาณ"

**วิธีใช้**
1. ในการ์ดตั้งค่า ติ๊ก **🧰 โหมดทำงานกับไฟล์ (Cowork)**
2. ช่อง **โฟลเดอร์ทำงาน** ใส่พาธโฟลเดอร์ที่ให้ AI ทำงานด้วย (ค่าเริ่มต้นคือโฟลเดอร์ `workspace` ข้างโปรแกรม) กด **📂 เปิดโฟลเดอร์** เพื่อเปิดดูใน File Explorer
3. ติ๊ก **✍️ อนุญาตสร้าง/แก้ไฟล์** ถ้าให้ AI เขียนได้ (ปิดไว้ = AI อ่านและค้นหาได้อย่างเดียว)
4. สั่งงานในแชตตามปกติ AI จะแสดงรายการสิ่งที่ทำกับไฟล์ท้ายคำตอบ

**เครื่องมือที่ AI มี:** ดูรายการไฟล์ (`list_files`), อ่านไฟล์ (`read_file` รองรับ txt/md/csv/json/โค้ด/pdf/docx), ค้นหาข้อความ (`search_text`), สร้างหรือเขียนไฟล์ทับ (`write_file`), แก้ไฟล์บางจุด (`edit_file`)

**ความปลอดภัย** (ออกแบบให้ AI พลาดแล้วเสียหายน้อยที่สุด)
- AI แตะได้ **เฉพาะในโฟลเดอร์ทำงาน** ทุกพาธถูกตรวจ กัน `..`, พาธเต็มนอกโฟลเดอร์ และ symlink
- **ไม่มีเครื่องมือลบไฟล์ และไม่มีเครื่องมือรันคำสั่ง/โปรแกรม**
- ก่อนเขียนทับหรือแก้ไฟล์เดิม จะ **สำรองของเดิมไว้ใน `.backups`** ในโฟลเดอร์ทำงานเสมอ ถ้า AI แก้ผิดให้เอาไฟล์จากที่นั่นกลับมา
- สร้าง/แก้ได้เฉพาะไฟล์ข้อความและโค้ด (ไม่มี `.exe` `.bat` `.ps1`) และไฟล์ที่ AI เขียนยาวไม่เกิน 200,000 ตัวอักษร
- ห้ามเลือกโฟลเดอร์ระบบ ไดรฟ์ทั้งลูก โฟลเดอร์ Home โฟลเดอร์ AppData หรือโฟลเดอร์ของโปรแกรมนี้ (กัน AI แก้โค้ดตัวเองและอ่านประวัติแชต)
- เนื้อหาในไฟล์ถูกบอกโมเดลว่าเป็น "ข้อมูล" ไม่ใช่คำสั่ง แต่โมเดลเล็กอาจหลงกลคำสั่งที่ซ่อนอยู่ในไฟล์ได้ **อย่าเปิดโหมดนี้กับโฟลเดอร์ที่มีไฟล์ที่ไม่น่าไว้ใจ**

**ข้อจำกัด**
- โมเดลต้องรองรับ tool calling ถ้าไม่รองรับจะมีข้อความแจ้ง (ลอง `qwen3:4b` หรือ `qwen3:8b`)
- โมเดลเล็ก (4B) เรียกเครื่องมือผิดพลาดได้บ้าง และทำได้ไม่เกิน `MAX_AGENT_STEPS` (6) ขั้นต่อ 1 คำสั่ง ให้สั่งทีละงานสั้นๆ จะแม่นกว่า
- ที่ว่างของโมเดลมีจำกัด (`NUM_CTX`) ผลลัพธ์การอ่านไฟล์แต่ละครั้งจึงยาวไม่เกิน `TOOL_RESULT_CHARS` ไฟล์ยาวจะถูกอ่านเป็นช่วงๆ ไม่ได้อ่านทั้งไฟล์ในครั้งเดียว
- โหมดนี้ไม่ใช้รูปที่แนบ และตอบทีเดียวหลังทำงานเสร็จ (ไม่สตรีมทีละคำ)

### แยกหน้าที่โมเดล (ทั่วไป / เขียนโค้ด)
```
หน้าจอ Local AI (Gradio)
        │
   backend/router.py  เลือกโมเดลตามคำถาม
        ├── โมเดลทั่วไป (MODEL)        ถามตอบทั่วไป วิเคราะห์เอกสาร ความรู้
        └── โมเดลเขียนโค้ด (CODE_MODEL) เขียนโค้ด Debug อธิบายโปรแกรม
        │
   ฐานความรู้ / ค้นเว็บ / ไฟล์แนบ  (ใช้ร่วมกันทั้งสองโมเดล)
```
การ์ด **โมเดล / Model** ด้านขวามี 3 โหมด

| โหมด | ทำอะไร |
|---|---|
| ตามคำถาม (Auto) | ค่าเริ่มต้น เดาจากคำถามว่าเป็นเรื่องโค้ดหรือไม่ |
| ทั่วไป (General) | ใช้โมเดลหลักเสมอ |
| เขียนโค้ด (Coding) | ใช้โมเดลเขียนโค้ดเสมอ |

โหมด Auto จัดเป็นเรื่องโค้ดเมื่อพบ: บล็อกโค้ด (```), ข้อความ error/traceback, ชื่อภาษาหรือเครื่องมือ (Python, SQL, Docker ฯลฯ), ชื่อไฟล์โค้ด (`app.py`), คำสั่ง SQL/ไวยากรณ์โค้ด, ไฟล์โค้ดที่แนบมา, หรือคำถามสั้นๆ ที่ต่อจากคำตอบที่เป็นโค้ด (เช่น "แก้ให้หน่อย") เป็นกฎง่ายๆ ที่เร็วและไม่เรียกโมเดลเพิ่ม **จึงพลาดได้บ้าง** ถ้าถูกเลือกผิด ให้บังคับโหมดเองด้วยการ์ดนี้ ท้ายคำตอบจากโมเดลโค้ดจะมีบรรทัด "ตอบโดยโมเดลเขียนโค้ด" ให้เห็นว่าใครตอบ

ข้อควรรู้
- **VRAM 4 GB วางโมเดลแชตได้ทีละตัว** เมื่อสลับระหว่างโมเดลทั่วไปกับโมเดลโค้ด Ollama ต้องโหลดโมเดลใหม่ ครั้งแรกที่สลับจะรอราว 3-10 วินาที (หน้าจอจะแจ้งสถานะ) ถ้าคุยสลับไปมาบ่อยจะรู้สึกช้า ให้บังคับโหมดเดียวไว้ตอนทำงานต่อเนื่อง
- โมเดลโค้ดไม่มีโหมดคิดลึก ตัวเลือก "คิดลึก" จึงไม่มีผลเมื่อโมเดลโค้ดตอบ
- โมเดลโค้ดอ่านรูปไม่ได้ ถ้าแนบรูปมาด้วย ระบบจะใช้โมเดลที่อ่านรูปได้แทน และจะไม่ดึงรูปจากไฟล์ PDF/Word มาประกอบคำตอบโค้ด
- โหมด Cowork ใช้โมเดลหลักเสมอ เพราะต้องเรียกเครื่องมือได้แม่นยำ
- ถ้ายังไม่ได้ `ollama pull qwen2.5-coder:3b` ระบบจะใช้โมเดลหลักตอบแทนพร้อมข้อความเตือน ติดตั้งแล้วใช้ได้ทันทีโดยไม่ต้องรีสตาร์ทแอป
- เปลี่ยนโมเดลโค้ดหรือปิดฟีเจอร์ได้ที่ `CODE_MODEL` ใน `backend/config.py` (ตั้งเป็น `""` = ปิด ใช้โมเดลหลักตัวเดียว)

### รูปจากไฟล์ PDF / Word
แนบไฟล์ PDF หรือ Word ที่มีรูปอยู่ในเนื้อหา แล้วถามเรื่องนั้น AI จะดึงรูปมาแสดงในคำตอบตรงตำแหน่งที่เกี่ยวข้อง

- ตอนแนบไฟล์ ชื่อไฟล์จะแสดงจำนวนรูปที่ดึงได้ เช่น `📎 manual.pdf · ... · 🖼️ 2 รูป`
- เลือกรูปที่เกี่ยวกับคำถามให้เอง: หน้าที่คุณระบุ (เช่น "ขอดูหน้า 2") มาก่อน ตามด้วยหน้าที่ถูกใช้ตอบ แล้วจึงรูปอื่น ส่งให้ AI ดูได้ไม่เกิน `DOC_IMAGES_PER_ANSWER` (3) รูปต่อคำตอบ
- AI วางรูปด้วยเครื่องหมายในคำตอบ ถ้าไม่ได้วาง รูปจะแสดงไว้ท้ายคำตอบแทน รูปไม่หาย
- รูปที่เล็กเกินไป (ไอคอน โลโก้) หรือเป็นเส้นยาวตกแต่ง จะถูกข้ามไป
- **การให้ AI "ดู" รูป** ต้องใช้โมเดลที่อ่านรูปได้ (`MODEL` หรือ `VISION_MODEL` ใน `backend/config.py`) ถ้าไม่มี AI จะตอบจากข้อความอย่างเดียว แต่ยังโชว์รูปใต้คำตอบให้
- ปิดฟีเจอร์ได้ทั้งหมดที่ `DOC_IMAGES = False` หรือปิดชั่วคราวด้วยช่องติ๊ก "ดึงรูปจากไฟล์มาประกอบคำตอบ"
- สำเนารูปเก็บในโฟลเดอร์ `doc_images` (ลบได้ตลอด จะถูกสร้างใหม่เมื่อแนบไฟล์อีกครั้ง) และเปิดให้เบราว์เซอร์โหลดเฉพาะโฟลเดอร์นี้เท่านั้น

### ประวัติแชต
- ทุกครั้งที่ AI ตอบเสร็จ แชตจะถูก **บันทึกอัตโนมัติ** ลงโฟลเดอร์ `chats` (ไฟล์ `.json` ต่อ 1 แชต) ปิดแอปแล้วเปิดใหม่ข้อมูลไม่หาย
- **เปิดแอปครั้งถัดไป** จะเปิดแชตล่าสุดต่อให้เลย (ปิดได้ด้วย `AUTO_RESUME_LAST_CHAT = False` ใน `backend/config.py`)
- การ์ด **ประวัติแชต** ด้านขวาแสดงแชตล่าสุด 30 อัน (`HISTORY_LIST_MAX`) กดเพื่อเปิดแชตเก่า ที่เหลือยังเก็บอยู่ในโฟลเดอร์
- ปุ่ม **＋** ด้านซ้ายเริ่มแชตใหม่ (แชตเดิมยังอยู่ในประวัติ)
- ปุ่ม **🗑 ลบแชตนี้** ลบแชตที่เปิดอยู่ ต้องกด 2 ครั้งติดกันเพื่อยืนยัน
- **ไฟล์และรูปที่แนบไม่ถูกเก็บในประวัติ** เปิดแชตเก่าแล้วต้องแนบใหม่ถ้าจะถามเกี่ยวกับไฟล์นั้นต่อ ส่วนข้อความที่คุยกันจะอยู่ครบ
- ไฟล์ใน `chats` เป็นข้อความธรรมดา (ไม่ได้เข้ารหัส) อย่าอัปโหลดโฟลเดอร์นี้ขึ้น GitHub หรือส่งให้ผู้อื่น (ไฟล์ `.gitignore` ที่ให้มาข้ามโฟลเดอร์นี้ให้แล้ว)

### แนบไฟล์และรูปในแชต
1. **กดปุ่มแนบ** ในช่องพิมพ์ หรือ **คัดลอกรูป/ไฟล์ไว้แล้วกด Ctrl+V** ในช่องพิมพ์ (เช่น แคปหน้าจอแล้ววางได้เลย)
2. แนบพร้อมกันได้ไฟล์เอกสารสูงสุด 5 ไฟล์ (ไฟล์ละไม่เกิน 20 MB) และรูปสูงสุด 4 รูป
3. ชื่อสิ่งที่แนบจะแสดงเหนือช่องพิมพ์ และอยู่ตลอดการคุย ถามต่อได้หลายคำถาม
4. กด **✖ ล้างไฟล์/รูป** เมื่อไม่ต้องการแล้ว
5. แนบแล้วกดส่งโดยไม่พิมพ์อะไร AI จะสรุปหรืออธิบายสิ่งที่แนบให้

**ไฟล์เอกสาร:** ไฟล์สั้น (รวมไม่เกิน 20,000 ตัวอักษร) ส่งให้ AI ทั้งไฟล์ ส่วนไฟล์ยาวระบบจะเลือกเฉพาะส่วนที่ตรงกับคำถามมากที่สุด ถ้าถามภาพรวมทั้งไฟล์ AI อาจเห็นไม่ครบ

**รูปภาพ:** ต้องใช้โมเดลที่อ่านรูปได้ ระบบจะตรวจให้เองว่า `MODEL` อ่านรูปได้หรือไม่ ถ้าไม่ได้ ให้ติดตั้งโมเดลอ่านรูปแล้วใส่ชื่อใน `VISION_MODEL` ตัวอย่าง:

```bash
ollama pull qwen2.5vl:7b
```

```python
VISION_MODEL = "qwen2.5vl:7b"   # ใน backend/config.py
```

รูปจะถูกย่อให้ด้านยาวไม่เกิน 1280 พิกเซลก่อนส่ง และถูกส่งใหม่ทุกคำถามจนกว่าจะล้าง ถ้าไม่ต้องการแล้วให้กดล้างเพื่อให้ตอบเร็วขึ้น

## ปรับแต่ง (ค่าอยู่ใน `backend/config.py`)

| ค่า | ความหมาย |
|---|---|
| `MODEL` | โมเดลที่ใช้ตอบคำถาม |
| `NUM_CTX` | ที่ว่างรวมของ prompt + ประวัติ + ข้อมูลอ้างอิง + คำตอบ ยิ่งมากยิ่งกิน RAM/VRAM |
| `MAX_TOKENS_FAST` / `MAX_TOKENS_THINK` | ความยาวคำตอบสูงสุด (โหมดปกติ / คิดลึก) |
| `HISTORY_MESSAGES` / `HISTORY_CHARS` | จำนวนข้อความและความยาวประวัติแชตที่ AI จำ |
| `FETCH_PAGES`, `WEB_TOP_PASSAGES` | จำนวนหน้าเว็บที่เปิดอ่าน / จำนวนชิ้นข้อมูลที่ส่งให้ AI |
| `KB_TOP`, `KB_MAX_DISTANCE` | จำนวนชิ้นจากฐานความรู้ / ความเข้มงวดในการเลือก (ยิ่งต่ำยิ่งเข้มงวด) |
| `CODE_MODEL`, `CODE_TEMPERATURE` | โมเดลเขียนโค้ด ("" = ปิด) / ค่าสุ่มของโมเดลโค้ด (ต่ำ = นิ่ง) |
| `FILE_FULL_CHARS`, `FILE_TOP_CHUNKS` | เกณฑ์ส่งทั้งไฟล์ / จำนวนชิ้นเมื่อไฟล์ยาว |
| `DOC_IMAGES`, `MAX_DOC_IMAGES`, `MIN_DOC_IMAGE_SIDE`, `DOC_IMAGES_PER_ANSWER` | เปิด/ปิดดึงรูปจากไฟล์ / ดึงได้กี่รูปต่อไฟล์ / ข้ามรูปที่เล็กกว่ากี่พิกเซล / รูปต่อคำตอบ |
| `VISION_MODEL`, `MAX_IMAGES`, `IMAGE_MAX_SIDE` | โมเดลสำรองอ่านรูป / จำนวนรูปสูงสุด / ขนาดรูปสูงสุดที่ส่ง |

> `NUM_CTX` ต้องเป็นค่าเดียวกันทุกการเรียก และตรงกับ `speed_test.py` ถ้าค่าเปลี่ยนไปมา Ollama จะโหลดโมเดลใหม่ทุกครั้งและช้าลงมาก

## ปรับให้เร็วที่สุดสำหรับเครื่อง (RTX 3050 4 GB / RAM 16 GB)

ค่าใน `backend/config.py` จูนไว้แล้ว หลักการคือ **ให้โมเดลอยู่บน GPU ทั้งหมด** เพราะเร็วกว่ารันครึ่ง CPU มาก

1. **เปิดแอปด้วย `start_local_ai.bat`** (ดับเบิลคลิก) ไฟล์นี้จะตั้งค่า Ollama ให้ประหยัด VRAM (`OLLAMA_FLASH_ATTENTION`, `OLLAMA_KV_CACHE_TYPE=q8_0`, `OLLAMA_NUM_PARALLEL=1`) รีสตาร์ท Ollama แล้วรัน `app.py` ให้ ไฟล์นี้จะปิด Ollama ที่เปิดอยู่ก่อนหน้า และ Ollama จะรันในหน้าต่างเล็กที่ย่อไว้ (ห้ามปิดหน้าต่างนั้นระหว่างใช้งาน)
2. **ตรวจว่าโมเดลอยู่บน GPU เต็มหรือไม่:** ถามคำถามหนึ่งข้อ แล้วพิมพ์ `ollama ps` ในอีกหน้าต่าง ช่อง PROCESSOR ควรเป็น **100% GPU**
   - ถ้าขึ้นเป็นสัดส่วน เช่น `40%/60% CPU/GPU` แปลว่า `NUM_CTX` ใหญ่เกิน ให้ลดลง (เช่น 6144)
   - ถ้าเป็น 100% GPU และ `nvidia-smi` ยังเหลือ VRAM เกิน ~500 MB ค่อยเพิ่ม `NUM_CTX` ทีละขั้น (12288 แล้วจึง 16384) พร้อมเพิ่ม `MAX_TOKENS_FAST` ตามได้
3. **เสียบสายชาร์จ และตั้งโหมดพลังงานของ Windows เป็น Best performance** โน้ตบุ๊กลดความเร็วลงมากเมื่อใช้แบตเตอรี่
4. ปิดโปรแกรมที่ใช้การ์ดจอ/แรมหนักๆ (เกม เบราว์เซอร์หลายแท็บ) ระหว่างใช้ เพราะ VRAM ว่างจริงมีแค่ราว 3.4 GB

สิ่งที่แอปทำให้เองเพื่อความเร็ว: โหลดโมเดลล่วงหน้าตอนเปิดแอป (`WARM_UP`), ค้างโมเดลไว้ 30 นาที (`KEEP_ALIVE`), ให้ bge-m3 รันบน CPU เพื่อเหลือ VRAM ให้โมเดลแชต (`EMBED_ON_CPU`), ใช้ 6 เธรด CPU ตามจำนวนคอร์จริง (`NUM_THREAD`), อัปเดตหน้าจอเป็นช่วงๆ ไม่ใช่ทุก token (`STREAM_INTERVAL`) และข้ามขั้นให้โมเดลเขียนคำค้นเมื่อคำถามสั้น
